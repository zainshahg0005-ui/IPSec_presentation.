IPsec & Virtual Private Networks (VPNs)

An Academic Presentation on Network-Layer Security, Protocol Suites, and Cryptographic Encryption

1. What a VPN Is & The Problem It Solves

Definition

A Virtual Private Network (VPN) creates a secure, encrypted "tunnel" across an untrusted public network, such as the internet.

The Core Problem

Data transmitted over public networks travels in plain text or minimally protected formats, making it vulnerable to eavesdropping, packet sniffing, and Man-in-the-Middle (MitM) attacks. A VPN guarantees that even if someone intercepts your traffic, they only see unreadable ciphertext.

Common Uses

  • Remote Access: Connecting remote or work-from-home employees securely to internal corporate applications and file servers.
  • Connecting Networks: Securely linking separate physical office networks (e.g., connecting a branch office to headquarters) over the public internet.

2. Primary VPN Types

Remote-Access VPN

Connects an individual user's device (laptop, smartphone) to a corporate network. It requires client software or built-in operating system tools on the user's endpoint to initiate the encrypted tunnel to the company gateway.

Site-to-Site VPN

Connects two entire local area networks (LANs) together over the internet using router-to-router or firewall-to-firewall setups. End users on either network do not need special client software installed.

3. How a VPN Differs from a Proxy

VPN (Network Layer - Layer 3)
Encrypts all system traffic coming from the entire operating system, including background services, system updates, and email clients.
Proxy (Application Layer - Layer 7)
Operates primarily at the application level. It reroutes traffic for specific applications (like a web browser) and masks the IP address, but generally does not encrypt system-wide network traffic by default.

4. What IPsec Is & How It Works

IPsec (Internet Protocol Security) is a standardized suite of open protocols developed by the IETF to secure IP communications at the Network Layer (Layer 3) of the OSI model.

Core Security Services Provided

  • Confidentiality: Encrypts data payloads to prevent unauthorized interception.
  • Integrity: Uses cryptographic hashing (HMAC-SHA2) to ensure data is not altered in transit.
  • Authentication: Verifies the identity of both endpoints before exchanging data.
  • Replay Protection: Uses sequence numbers to prevent attackers from retransmitting valid data packets.

Key Protocols

IKE / IKEv2 (Internet Key Exchange):
Manages identity authentication, negotiates security parameters, and generates shared keys.
ESP (Encapsulating Security Payload):
Provides encryption, integrity verification, data-origin authentication, and anti-replay protection.
AH (Authentication Header):
Provides authentication and integrity, but no encryption. Rarely used today as it breaks passing through NAT devices.

5. IPsec Operational Modes

Transport Mode

Encrypts only the payload (the actual data layer) of the IP packet, leaving the original IP header unencrypted and visible. Typically used for host-to-host communication.

Tunnel Mode

Encrypts the entire original IP packet (both header and payload) and wraps it inside a brand-new outer IP header. Typically used for site-to-site VPNs and remote-access VPNs.

6. Simple Connection Architecture

DATA FLOW PROCESS MAP
  1. Laptop Client: Runs an IPsec VPN client and encrypts outgoing data locally.
  2. Public Internet: Encrypted packets (ESP) travel over untrusted public routers safely.
  3. Company VPN Gateway: Terminates the tunnel, decrypts traffic, and verifies packet integrity.
  4. Internal Network: Decrypted packets are routed securely to internal company servers.

7. Benefits and Limitations

Benefits

  • Provides robust security, privacy, and packet integrity at Layer 3.
  • Transparent to higher-level user applications.
  • Enables standardized, secure network-to-network connectivity across multi-vendor equipment.

Limitations

  • High configuration and management complexity (SAs, policies, proposals).
  • Performance latency and CPU overhead from cryptographic processing and enlarged packet headers.
  • Does not stop application-level malware, phishing, or compromised user credentials once inside the perimeter.

9. Real-World Walkthrough Scenario

EXECUTION TRACE // SECURE CONNECTION

Scenario: An employee sitting at a public coffee shop connects remotely to an organization's internal network.

  1. The employee opens their laptop's VPN client and enters credentials along with a multi-factor authentication (MFA) code.
  2. Phase 1 (IKE Negotiation) executes a Diffie-Hellman exchange to authenticate the user and establish a secure control tunnel with the company firewall.
  3. Phase 2 negotiates symmetric encryption keys (e.g., AES-256) for the actual data tunnel.
  4. The employee accesses an internal company server. The VPN client wraps this request into an ESP packet and transmits it across the internet.
  5. The corporate VPN gateway receives the packet, decrypts it, verifies authenticity, and forwards it to the intranet server, returning the response back through the encrypted tunnel.

10. Conclusion

VPNs serve as a primary defense for securing communication over untrusted public infrastructure. IPsec provides complete Network Layer protection—delivering confidentiality, integrity, authentication, and anti-replay protection through the combination of IKE key negotiation and ESP packet encryption.
